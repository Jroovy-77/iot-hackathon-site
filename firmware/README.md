## คำสั่ง (ติดตั้ง PlatformIO แล้ว: `pip install platformio`)
```bash
cd firmware
python -m platformio run -e house -e receiver        # คอมไพล์
python -m platformio run -e receiver -t upload        # อัปโหลดลงบอร์ดที่เสียบอยู่
python -m platformio device monitor -f log2file       # ดู Serial + เก็บ log เป็นไฟล์
python -m platformio test -e native                   # เทสต์บนคอม (ไม่ต้องมีบอร์ด)
```

## โปรแกรม
- **ping / pong (B2):** บอร์ด A อัป `ping` บอร์ด B อัป `pong` · เปิด Serial บอร์ด A พิมพ์ `g` → ส่ง 50 รอบ · บรรทัดท้าย `SUMMARY,ok=..,pct=..,avg_rssi=..,avg_snr=..,PASS/FAIL` (ผ่าน ≥ 48/50) · วิทยุส่งหลังพิมพ์ `g` เท่านั้น
- **receiver:** ต่อโน้ตบุ๊ก เปิด `dashboard/?live=1` ใน Chrome/Edge → "เชื่อมต่อตัวรับ (สาย USB)" · Serial ออกเป็น JSON (`snap` `hb` `res`) ตาม `docs/data-contract.md` ข้อ 5 · บรรทัด `# RX …` `# TX …` คือ log วิทยุ (แดชบอร์ดทิ้งเอง) ใช้เป็นหลักฐานได้
- **house:** พิมพ์ใน Serial ได้ (ใช้ตอนยังไม่ได้ต่อปุ่ม): `r` = แดงกดค้าง · `g` = เขียวกดสั้น · `G` = เขียวกดค้าง · `s` = สถานะ · log `TX` `RX` `VOICE` `STATE` `PROBE`
- ถ้า `RADIO begin=` ไม่ใช่ 0 → หยุด เช็กสาย SPI / NSS / 3V3 แล้วรายงานพร้อมเลขนั้น (เช่น −2 = หาชิปไม่เจอ)

## สิ่งที่ตัดสินใจไว้ (บอกผู้ใช้แล้ว 29 ต.ค.)
- Coding rate **4/5** (เอกสารเดิมใน wiring-breadboard ข้อ 5 เขียน 4/7 — แก้ให้ตรง data-contract 4.1)
- รอบนี้ **ไม่หลับลึก** (เสียบ USB) จึงใช้เสียงนำ 8 ทุกข้อความ (data-contract 4.4 ใช้ 500 สำหรับกล่องที่หลับ — ใช้คืนตอนทำกล่องจริง)
- เสียงเป็น **บี๊ป** แต่ละรหัสจังหวะต่างกัน (ยังไม่มีไฟล์เสียงพูด) · แหวนไฟสว่างสุด 64/255 (25%)
- ทดสอบเร็ว: ใส่ `-D TIME_SCALE=360` ใน build_flags (6 ชม. → 60 วิ) แดชบอร์ดจะได้ `cfg.speedup`
- ตัวรับไม่สร้างคำขอคืนจาก flag `open_req` ตอนรีสตาร์ต (กันเปิดคำขอที่ปิดแล้วซ้ำ) — คำขอที่เปิดค้างตอนตัวรับรีสตาร์ตจะกลับมาเมื่อกล่องกดใหม่

## กฎ
ความถี่ 920–925 MHz เท่านั้น (คอมไพล์ไม่ผ่านถ้าตั้งผิด) · EIRP ≤ 17 dBm · ห้ามจ่าย 5V เข้าวิทยุ · ต่อเสาก่อนเสียบไฟทุกครั้ง
