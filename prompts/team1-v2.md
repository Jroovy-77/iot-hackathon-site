# ทีม 1 · ไอเดียรุ่น 2 · แดชบอร์ด "กล่องคุยสองทาง"

คุณคือ **lead ของทีม 1** อ่าน `CLAUDE.md` แล้วอ่าน `docs/idea.md` หัวข้อ "สรุปสั้น" ถึง "คำตัดสินของผู้ใช้" (ไม่ต้องอ่านต้นฉบับท้ายไฟล์) และ `docs/design-direction.md`

## เช็กก่อนเริ่ม
- ถ้ายังไม่มีโฟลเดอร์ `_archive/boat-button-v1/` หรือ `dashboard/` ยังมีไฟล์ `app.js` เก่าอยู่ → หยุด บอกผู้ใช้ (ภาษาไทย) ให้ดับเบิลคลิก `archive-v1.bat` ก่อน
- ถ้ายังไม่มี `docs/design-direction.md` → หยุด บอกผู้ใช้ให้กลับไปเลือกทิศทางหน้าตาในแชทก่อน

## การอนุมัติล่วงหน้าจากผู้ใช้
- ทำต่อจนจบได้เลย ไม่ต้องหยุดถาม ยกเว้นสิ่งที่ย้อนกลับไม่ได้ และการแตะไฟล์นอกโฟลเดอร์นี้
- lead ยืนยันข้อเสนอ architect เองได้ถ้าตรงกับสถาปัตยกรรมใน idea.md บันทึกเหตุผลในรายงาน
- ยังไม่ deploy / push
- ข้อสงสัยท้าย `docs/parts.md` และ "คำชั่วคราว" ใน idea.md: ห้ามแก้เอง สรุปในรายงานให้ผู้ใช้ตัดสิน
- แตะได้เฉพาะ `dashboard/`, `docs/data-contract.md`, `docs/wiring.md`, `index.html`, `preview.bat` และรายงานของตัวเอง

## สร้างทีม (งานใหญ่ = ทีมเต็ม)
สร้าง **agent team** spawn 3 คน ตามไฟล์บทบาท (ไม่ต้องระบุ model):
- `architect` (dash-architect) · `builder` (dash-builder) · `critic` (dash-critic)
ข้อความตอน spawn บอก: นี่คือไอเดียรุ่น 2, ไฟล์ที่ต้องอ่าน (ตามด้านบน + `docs/parts.md`), การอนุมัติล่วงหน้า และ "ห้ามใช้ /impeccable แบบเต็มในทีม"
ปิด teammate ทันทีที่งานของเขาเสร็จ

## ผลงาน
1. **`docs/data-contract.md`** (architect) เขียนใหม่ทั้งไฟล์ บนสุดมี `## สรุปสั้น` ≤ 30 บรรทัด
   - **ชื่อสถานะกลาง** ที่ทีม 2 จะใช้ตรงกัน: `warn` (ส้ม) · `heard` (เขียว) · `silent` (ไม่ตอบใน 6 ชม.) · `sos` (แดง) · `retry` (ส่งไม่ถึง กำลังลองใหม่) · `accepted` (เหลือง) · `done` (เขียว) · `auto_sos` (แดง ขอแทน รอ อสม. ยืนยัน) · `low_batt` (ถ่านอ่อน)
   - ทิศทางลง: คำเตือน (ระดับน้ำ + สิ่งที่ต้องทำ + รหัสข้อความเสียง), ACK, รับเรื่อง, เสร็จ · ทิศทางขึ้น: ได้ยินแล้ว, ขอช่วย, ขอแทน, น้ำถึงสายวัด (ใช่/ไม่ใช่ — ไม่ใช่ค่าความลึก), แบต · คำเตือนพูดซ้ำทุก 10 นาทีจนกว่าจะกด (ค่าออกแบบ)
   - ขนาดข้อความ LoRa เป็นไบต์ + เวลาส่งโดยประมาณ (AS923) + วิธีส่งคำเตือนซ้ำให้กล่องที่ฟังเป็นช่วง ๆ ได้ยิน (ข้อสงสัยข้อ 7 ใน parts.md)
   - 1 บ้าน = 1 ID = 1 คำขอที่เปิดอยู่ · หน้าเว็บคุยกับตัวรับผ่าน Wi-Fi ในพื้นที่ (เลือกวิธีที่ ESP32 ทำได้ พร้อมเหตุผล)
2. **`dashboard/`** (builder) เขียนใหม่ทั้งหมด ไม่มีเน็ตก็ต้องใช้ได้ (ไม่มี CDN / web font ภายนอก / tile) บอกขนาดไฟล์รวมในรายงาน
   - **โหมดจำลองเป็นหลัก** (PoC ไม่มีอุปกรณ์จริง) ป้าย "จำลอง" ที่เดียวชัด ๆ · โหมดข้อมูลสดเตรียมจุดต่อตาม contract ไว้พอ ไม่ต้องทำครบ
   - **แผนที่ชุมชนจำลองเป็นสิ่งเด่นที่สุด** บ้านละ 1 หมุด สีหมุดใช้สีสถานะตาม idea.md เท่านั้น
   - **หน้าผู้ส่งคำเตือน (อปท./ปภ. — จำลอง):** เลือกพื้นที่ + เลือกคำ วันนี้ / คืนนี้ / พรุ่งนี้ (ข้อความเสียงตาม idea.md) → ส่ง → เห็นตัวนับ "ได้ยินแล้ว X / ยังเงียบ Y"
   - **รายการ "บ้านที่ยังเงียบ"** เรียงบ้านติดเตียงก่อน แล้วตามเวลาที่เงียบ ใช้เป็นรายการให้ อสม. ไปเคาะ ("เงียบ = ได้รับความสนใจมากขึ้น")
   - **คิวขอความช่วยเหลือ** บ้านละ 1 รายการ ปุ่ม "รับเรื่อง" / "ช่วยเสร็จ" · บ้านเดิมกดซ้ำ → ไม่เพิ่มรายการ · `auto_sos` ขึ้นลำดับแรกพร้อมปุ่ม "อสม. ยืนยัน" ก่อนส่งเรือ
   - **แผงกล่องบ้านจำลอง** ของบ้านที่เลือก: สีวงแหวนไฟ + ประโยคที่กล่องพูด (ใช้คำใน idea.md ทุกคำ)
   - **เดโม 60 วิ ตาม idea.md ทุกขั้น** (รวมฉากเปิด "Cell Broadcast เข้ามือถือที่ยายไม่ได้ใช้") · `?demo=auto` เล่นเอง · `?at=<วินาที>` กระโดดไปจุดนั้น · ป้าย "เดโมเร่งเวลา" ตอนย่อ 6 ชม. / 2 ชม.
   - แผงควบคุมเดโมแยกเป็นโหมดพรีเซนต์ ไม่ปนกับหน้าใช้งาน
   - ตัวเลขที่ออกแบบเองติด "ค่าออกแบบ จะปรับหลังทดสอบ" · ตัวเลขสถิติใช้เฉพาะ "กติกาตัวเลข" ใน idea.md พร้อมแหล่งที่มา
   - ใช้ดีบนมือถือ 390×844 (อสม./ทีมใช้มือถือ) และจอ 1280×720 (พรีเซนต์)
   - ทำตาม `docs/design-direction.md` + `.claude/skills/impeccable/reference/craft-floor.md`
   - **บทเรียนรอบก่อน (ผู้ใช้ไม่ชอบ "AI สล็อป"):** ห้ามทุกอย่างสำคัญเท่ากัน ห้ามป้ายซ้ำ ห้ามกรอบซ้อนเยอะ
   - ถ้าอยากดูวิธีวาดแผนที่จากรุ่น 1: Grep ใน `_archive/boat-button-v1/dashboard/app.js` เฉพาะส่วนที่ต้องการ ห้ามอ่านทั้งไฟล์ และห้ามลอกหน้าตาเดิม
2b. **`docs/wiring.md`** (architect) ผังต่อสายรุ่นชาวบ้านตาม `docs/parts.md` (ใช้ Wio-SX1262) — ทีม 2 จะวาดฉาก Wiring Diagram จากไฟล์นี้ บนสุดมี `## สรุปสั้น`
   - ตารางขา: ชิ้น → ขาของชิ้น → ขา ESP32-C3 Super Mini (GPIO) / รางไฟ / กราวด์ + ตัวต้านทาน/ตัวเก็บประจุที่ใส่ระหว่างทาง พร้อมค่า
   - เช็กข้อจำกัดในหัวข้อ "ผังต่อสาย" ของ parts.md กับ datasheet จริง (ขาปลุกจากหลับ, strapping, ขาไม่พอ, ไม่มี DAC, ระดับแรงดัน, กันไฟย้อน) ระบุลิงก์ datasheet ที่ใช้
   - รายการเส้นสายแบบอ่านด้วยเครื่องได้ (ตาราง `from` / `to` / `type` = power | ground | data | audio) ให้ทีม 2 ใช้ได้ตรง ๆ
   - งบไฟโดยประมาณ: ตอนหลับ/ฟัง/เตือน/ขอช่วย และอายุถ่าน AA ตอนไฟดับ (เขียนว่าประมาณการ)
   - ข้อสงสัยที่เจอเพิ่ม ใส่ท้ายไฟล์ ห้ามแก้ parts.md
3. **`index.html` ที่ root** (architect) อัปเดตชื่อเป็นรุ่น 2 · `preview.bat` ไม่ต้องแก้ถ้ายังใช้ได้
4. **`dashboard/REVIEW.md`** (critic) เก็บเฉพาะประเด็นที่ยังเปิด ≤ 80 บรรทัด · รันตัวตรวจอัตโนมัติตาม `tools/README.md` ก่อนดูภาพ · builder แก้ข้อ "ต้องแก้" ให้ครบ
