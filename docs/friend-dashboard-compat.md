# แดชบอร์ดของเพื่อน (FloodLink-Full-Package-20261028) ต่อกับตัวรับ/กล่องของเรายังไม่ได้ เพราะอะไร

เขียน 9 พ.ย. 2569 · ตรวจจากไฟล์ในซิปโดยอ่านตรง ๆ (ไม่ได้รันโปรแกรมของเพื่อน) · ฝั่งเรา: `docs/data-contract.md` ข้อ 4–5 และ `firmware/common/radio_config.h`

## เหตุผล 4 ข้อ (เรียงจากที่ทำให้พังก่อน)

1. **แดชบอร์ดทิ้งทุกบรรทัดที่ตัวรับของเราส่งไป**
   - ของเพื่อน (`05-Dashboard-Bench/public/serial.js` ฟังก์ชัน `readLoop`) ยอมรับเฉพาะบรรทัดที่มี `"v":1` และมีช่อง `"type"` เป็น `gateway`, `heartbeat`, `sos`, `auto_sos`, `safe`, `warning_ack`, `command_ack`
   - ของเรา ส่ง `{"t":"snap","v":2,...}` และ `{"t":"hb",...}` (ใช้ช่อง `t` ไม่ใช่ `type`, `snap` เป็น v2, `hb` ไม่มี `v`) → แดชบอร์ดขึ้นแค่ "ข้ามข้อมูลที่ไม่ใช่ FloodLink protocol v1" ไม่มีบ้านขึ้นเลย
2. **แดชบอร์ดไม่ยอมส่งคำสั่งถ้าค่าวิทยุไม่ตรงของเขา**
   - `gateway-profile.js` บังคับ SX1276 · 923.2 MHz · 125 kHz · **SF7** · CR5 · sync 0x12 · กำลังส่งไม่เกิน **10 dBm** และต้องได้บรรทัด `type:"gateway"` ที่ `ready:true`
   - ของเรา **SF9 · 14 dBm** (`radio_config.h`) และตัวรับเรายังไม่ส่งบรรทัด `gateway` ปุ่มส่งคำเตือน/รับเรื่อง/ช่วยเสร็จจะถูกบล็อก
3. **คำสั่งที่แดชบอร์ดส่งออกตัวรับของเราไม่รู้จัก**
   - ของเพื่อน ส่ง `{"v":1,"type":"command","id":...,"homeId":"...","command":"warning|accepted|dispatched|resolved","payload":{...}}` ข้อความคำเตือนเป็นข้อความอิสระ ≤160 ตัวอักษร และรหัสบ้านเป็นข้อความ
   - ของเรา รับ `{"cmd":"hello|warn|warn_stop|confirm|accept|done|cancel_ok","rid":n,...}` คำเตือนเป็นรหัส `when` (`today`/`tonight`/`tomorrow`) + `lvl_cm` กล่องพูดเสียงสำเร็จรูปจึงไม่มีข้อความอิสระ รหัสบ้านเป็นเลข 1–65534
4. **หน้าที่ของตัวรับต่างกัน (ต้นเหตุของข้อ 1–3)**
   - ของเพื่อน ตัวรับเป็นแค่ท่อส่งต่อ เก็บสถานะ/คำขอ/ตอบรับในฐานข้อมูลบนคอม (backend SQLite)
   - ของเรา ตัวรับถือสถานะเอง ส่ง ACK ให้กล่อง ส่งซ้ำ กันคำขอซ้ำ แล้วส่งภาพรวม `snap` ทั้งก้อนให้เว็บ เว็บเป็นแค่หน้าจอ + ปุ่มสั่ง

ค่าที่ตรงกันอยู่แล้ว: ความถี่ 923.2 MHz · BW 125 kHz · CR 4/5 · sync 0x12 · USB 115200 · หนึ่งบรรทัดหนึ่ง JSON จบด้วย LF

## ทางแก้ที่น่าจะง่ายสุด: ให้แดชบอร์ดเพื่อน "พูดภาษาเรา" ที่ฝั่ง USB (ไม่ต้องแตะเฟิร์มแวร์ของเรา)

- รับบรรทัด `snap` / `hb` / `res` ตาม `data-contract.md` ข้อ 5.2–5.3 แล้วแปลงเป็นข้อมูลภายในของเขา (ใช้ `houses[]`, `req`, `warn`, `events[]` ตามนั้น)
- ส่งคำสั่งเป็น `{"cmd":...,"rid":...}` ตามข้อ 5.4 และรอ `snap` ยืนยัน ไม่เปลี่ยนสถานะบนจอเองก่อน (ข้อ 5.4 ท้ายตาราง)
- เอาการเช็ก profile SF7/10 dBm ออก หรือเปลี่ยนเป็น SF9/14 dBm และเปิดให้ส่งได้เมื่อได้ `snap` ล่าสุด (ตัวรับเราไม่ส่ง `ready`)
- เริ่มด้วยการส่ง `{"cmd":"hello"}` เมื่อเปิดพอร์ต (ข้อ 5.1)

ทางที่หนักกว่า: เปลี่ยนเฟิร์มแวร์กล่องบ้านของเราให้พูดโปรโตคอล FL ของเขา ซึ่งเขาเขียนไว้เองว่าฝั่งกล่องบ้านยังไม่มี ไม่แนะนำ
