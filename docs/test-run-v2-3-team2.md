# รายงานทีม 2 รอบ v2-3 · ตัวรับ + จำลองส่ง-รับสัญญาณ (ฉาก 8)

## ทำอะไร
- ฉาก 8 อัปเกรด: กล่องติดผนังชั้นบนในห้อง (สูง 1.2–1.4 ม. ค่าออกแบบ) · ส่งข้อความวิทยุแล้วซูมออกเป็นแผนที่จำลอง คลื่นวิ่งจากบ้านไป อบต. แล้ว ACK วิ่งกลับ
- ตัวรับรุ่นชาวบ้านที่ อบต. ชั้นบนสุด + โน้ตบุ๊ก (ปุ่ม "ดูตัวรับ") · จอ Serial ของตัวรับ · ปุ่มสัญญาณ ดี / อ่อน / ขาด
- ระยะบนแผนที่ใช้เฉพาะตัวเลขจากงานวิจัย 2 ชิ้น (มีลิงก์) + ช่อง "ระยะของกล่องเรา: รอผลทดสอบ 25 ต.ค."
- ทีม: modeler + animator ทำเสร็จก่อนผมมาตรวจ (ผมเป็นคนตรวจและปิดงาน) · ไม่มี teammate เหลือเปิดอยู่

- กดแดงค้าง 2.5 วิ เรื่องที่ 2:
  - **ดี:** Serial 2 บรรทัด (รับ SOS "ครั้งที่ 1" + ส่ง ACK 0.14 วิ)
  - **อ่อน:** Serial เห็นแค่ "ครั้งที่ 2" · seq เดิม (12)
  - **ขาด:** Serial ว่าง · หลังพลาดครั้งที่ 3 กล่องพูด "ยังส่งไม่ถึง กำลังลองใหม่" · เร่งเวลาถึง 13 ชม. จอโน้ตบุ๊กขึ้น "ขาดการติดต่อ"
- เวลาออกอากาศในโค้ดตรงตาราง 4.3: ขึ้น/ACK 144 · WARN 2,180 · ACCEPTED/DONE 2,160 ms · 923.2 MHz SF9/BW125 +14 dBm ติด "ค่าออกแบบ"
- ทั้ง 3 โหมดและ `?still=1`: console ไม่มี error · ไม่มีคำขอออกนอกเครื่อง · ภาพนิ่งแผนที่โหลดได้ (1280 px) · คำพูดกล่อง 8 ประโยคตรง idea.md คำต่อคำ
- ภาพ 1280×720 และ 390×844: กล่องในบ้าน · แผนที่ระหว่างคลื่นวิ่ง · ตัวรับใน อบต. · จอ Serial · ภาพนิ่ง — ป้ายบนมือถืออ่านออก
- ตัวตรวจอัตโนมัติ (impeccable detect) เจอ 1 ข้อ: ข้อความซ่อนก่อนเลื่อนถึง — เป็นการออกแบบของหน้าเลื่อน (มีโหมดภาพนิ่ง/noscript รองรับ) ไม่ใช่ข้อผิด

## เรื่องที่ผู้ใช้ต้องตัดสิน
1. **ตำแหน่งแนะนำ** (อบต. ชั้นบนสุด · เสาบนหลังคา · สายเสาสั้น · พาวเวอร์แบงก์ / กล่องติดผนังชั้นบนใกล้หน้าต่างฝั่ง อบต.) เป็นข้อเสนอของ lead ยังเป็นข้อความบนเว็บ — **แนะนำ:** ใช้ตามนี้ แล้วปรับหลังทดสอบ
2. **ระยะ 0.8 กม. ของแผนที่** เป็นค่าสมมติของแผนที่จำลอง (ติดป้ายแล้ว) · ถ้ากรรมการถามระยะของกล่องเรา ต้องรอวัดจริง 25 ต.ค. แล้วใส่ใน `OUR_RANGE_M` บนสุดของ `scroll.js`
3. ฉาก 8 มีคำว่า "จำลอง" หลายที่ (ผู้ใช้รับได้ตั้งแต่ v2-2)
