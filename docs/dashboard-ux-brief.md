# FloodLink แดชบอร์ด: เอกสารสำหรับออกแบบ UX/UI (ฉบับละเอียด)

เขียน 9 พ.ย. 2569 สำหรับเพื่อนที่จะออกแบบหน้าจอใหม่ให้ใช้กับกล่องบ้าน + ตัวรับของทีมเรา
แหล่งความจริงทางเทคนิค: `docs/data-contract.md` (v2) · ทิศทางหน้าตาเดิม: `docs/design-direction.md` · ไอเดีย: `docs/idea.md`
ทำไมแดชบอร์ดชุดเดิมของเพื่อน (FloodLink-Full-Package-20261028) ต่อของเราไม่ได้: `docs/friend-dashboard-compat.md`

> **กติกาตัวเลข:** ตัวเลขเวลา/เกณฑ์ทุกตัวในเอกสารนี้เป็น **ค่าออกแบบ จะปรับหลังทดสอบ** (มาจาก data-contract) ยกเว้นในหัวข้อ 11 ที่เป็นผลทดสอบจริง ห้ามเอาค่าออกแบบไปเขียนบนหน้าจอเหมือนเป็นผลวัด

---

## 0. อ่านก่อน (สรุป 10 บรรทัด)

1. แดชบอร์ดคือหน้าจอของ **ทีมช่วยเหลือ / อสม. / เจ้าหน้าที่ อบต.** ใช้ดูว่าบ้านไหนได้ยินคำเตือน บ้านไหนเงียบ บ้านไหนขอความช่วยเหลือ แล้วกดสั่งกลับไปที่กล่อง
2. เปิดบน **โน้ตบุ๊กเครื่องเดียว** ที่เสียบ **ตัวรับ** ทางสาย USB ใช้ **Chrome หรือ Edge เท่านั้น** (Web Serial) **ไม่มีอินเทอร์เน็ต** ห้ามโหลด CDN, ฟอนต์, แผนที่ออนไลน์
3. **ตัวรับเป็นคนตัดสินสถานะ** หน้าเว็บมีหน้าที่แค่ **แสดงผล + ส่งคำสั่ง** ห้ามเปลี่ยนสถานะบนจอเองก่อนตัวรับยืนยัน
4. บ้านแต่ละหลังมีสถานะหลักได้ **10 ค่า** + ป้ายซ้อน (ถ่านอ่อน, ขาดการติดต่อ, ยกเลิกโดยบ้าน) ดูหัวข้อ 3
5. **สีมีความหมายเดียว:** ส้ม = เตือน รอคนตอบ · เขียว = ได้ยินแล้ว / ช่วยเสร็จ / ปลอดภัย · แดง = ขอความช่วยเหลือ · เหลือง = ทีมรับเรื่องแล้ว · เทา = ไม่มีเหตุ / เงียบ / ขาดการติดต่อ
6. **1 บ้าน = 1 คำขอที่เปิดอยู่** ไม่มีคำขอซ้ำบนจอ (ถ้าบ้านกดซ้ำ ตัวรับนับใน `req.dup`)
7. งานหลัก 5 อย่าง: ส่งคำเตือน → ดู "บ้านที่ต้องไปดู" (เงียบ / ขาดการติดต่อ) → รับคำขอ → ส่งทีม/ปิดงาน → จัดการกรณีพิเศษ (ขอแทน, ยกเลิกโดยบ้านติดเตียง)
8. ทุกเวลาจากตัวรับเป็น **วินาทีนับจากตัวรับเปิดเครื่อง** ต้องแปลงเป็นนาฬิกาจริงบนจอ (หัวข้อ 6.4)
9. ต้องออกแบบ **สถานะการเชื่อมต่อ** ให้ชัด (ยังไม่ต่อ / ต่อแล้ว / ขาดการเชื่อมต่อ) เพราะคนใช้จริงอาจเผลอดึงสาย
10. ต้องมี **โหมดจำลอง** ที่ใช้ข้อมูลรูปเดียวกัน (ใช้พรีเซนต์/ทดสอบโดยไม่มีกล่อง) และมีป้าย "จำลอง" ชัด ๆ ที่เดียว

## 1. ระบบทำงานยังไง

```
[กล่องบ้าน x N] --วิทยุ LoRa 923.2 MHz--> [ตัวรับ ESP32-C3 + SX1276] --สาย USB--> [โน้ตบุ๊ก: Chrome/Edge + แดชบอร์ด]
       ^                                       |  เก็บสถานะทุกบ้าน ตัดสินสถานะ ส่ง ACK ส่งซ้ำ
       +----------- วิทยุ (ทิศลง) -------------+
```

| ใคร | ตัดสินอะไร |
|---|---|
| **กล่องบ้าน** | กดค้าง 2 วิ, น้ำขึ้น, ขอแทนอัตโนมัติ, ถ่านอ่อน, ส่งซ้ำเมื่อไม่ได้ ACK (ทำงานได้แม้ไม่มีใครเปิดเว็บ) |
| **ตัวรับ** | สถานะของทุกบ้าน, บ้านเงียบ, ขาดการติดต่อ, เปิด/ปิดคำขอ, ส่งคำเตือน/รับเรื่อง/เสร็จ ไปที่กล่อง |
| **แดชบอร์ด** | แสดงผลให้คนตัดสินใจ + ปุ่มสั่ง (เตือน, หยุดเตือน, ยืนยันขอแทน, รับเรื่อง, เสร็จ, โทรแล้วปลอดภัย) |

สิ่งที่คนที่บ้านเห็น/ได้ยิน (ช่วยให้ออกแบบคำบนจอให้ตรงกับที่ชาวบ้านได้ยิน):

| เหตุการณ์ | ไฟบนกล่อง | เสียงที่กล่องพูด (ค่าออกแบบ) |
|---|---|---|
| ได้รับคำเตือน | ส้มกะพริบ | "เตือนภัยน้ำท่วม น้ำจะเข้าบ้านภายใน วันนี้/คืนนี้/พรุ่งนี้ ยกของขึ้นที่สูง พาคนป่วยขึ้นชั้นบน ได้ยินแล้วกดปุ่มเขียว" (ซ้ำ 10 ครั้งแรกทุก 1 นาที แล้วทุก 5 นาที) |
| กดเขียวตอนเตือน | เขียว | "ขอบคุณ ทีมรู้แล้วว่าบ้านนี้ได้ยิน" |
| กดแดงค้าง 2 วิ | แดง | "ส่งขอความช่วยเหลือแล้ว รอสักครู่" |
| ทีมกด "รับเรื่อง" | เหลือง | "ทีมรับเรื่องแล้ว เรือกำลังมา อยู่บนที่สูง อย่าลงน้ำ" |
| ทีมกด "ช่วยเสร็จ" | เขียว | "ทีมช่วยเหลือบ้านนี้เรียบร้อยแล้ว" |
| กล่องขอแทน (ติดเตียง) | แดง | "น้ำเข้าบ้านแล้ว กล่องขอความช่วยเหลือให้แล้ว" |
| กดเขียวค้าง 2 วิ | เขียว | "ยกเลิกคำขอแล้ว ทีมรู้ว่าบ้านนี้ปลอดภัย" |
| ถ่านอ่อน | ไม่เปลี่ยน | "ถ่านใกล้หมด กรุณาเปลี่ยนถ่าน" |
| ส่งไม่ถึง | สีเดิม | "ยังส่งไม่ถึง กำลังลองใหม่" (แดชบอร์ด **ไม่รู้** ตอนนี้ เห็นภายหลังเป็น `try` > 1) |

## 2. ผู้ใช้หน้าจอ และงานที่ต้องทำ

| ผู้ใช้ | อยู่ที่ไหน | อยากรู้อะไรเร็วที่สุด | กดอะไร |
|---|---|---|---|
| ผู้ส่งคำเตือน (อปท./ปภ.) | อบต. ชั้นบน | ส่งออกไปแล้วไหม ถึงกี่บ้าน กี่บ้านตอบ | ส่งคำเตือน, หยุดส่งซ้ำ |
| อสม. | ภาคสนาม (โทรคุยกับคนที่โน้ตบุ๊ก) | บ้านไหนเงียบ / ขาดการติดต่อ (ติดเตียงก่อน) ต้องไปเคาะ | ยืนยันคำขอแทน (`confirm`) |
| ทีมช่วยเหลือ / คนคุมโน้ตบุ๊ก | อบต. หรือบนเรือ | คิวคำขอเรียงตามความเร่ง บ้านอยู่ตรงไหน ติดเตียงไหม น้ำขึ้นไหม | รับเรื่อง, ช่วยเสร็จ, โทรแล้วปลอดภัย |

**คำถามที่หน้าจอแรกต้องตอบได้ใน 3 วินาที (ข้อเสนอ):**
1. ตอนนี้ต่อกับตัวรับอยู่ไหม และข้อมูลสดไหม
2. มีคำขอที่ยังไม่มีคนรับกี่บ้าน (แดง) ใครก่อน
3. ถ้ามีคำเตือนค้าง: ตอบแล้วกี่บ้าน ยังเงียบกี่บ้าน (ติดเตียงกี่บ้าน) ขาดการติดต่อกี่บ้าน

## 3. สถานะของบ้าน (ฟิลด์ `state` มีได้ 10 ค่าเท่านั้น)

| `state` | คำบนจอ (ข้อเสนอ) | สี | ทีมควรทำอะไร | ใครเปลี่ยน |
|---|---|---|---|---|
| `idle` | ไม่มีเหตุ | เทาเส้นบาง | — | — |
| `warn` | ได้รับคำเตือน รอคนในบ้านตอบ | ส้ม `#E0701A` | รอ | ตัวรับ (หลังส่งคำเตือน) |
| `heard` | ได้ยินแล้ว | เขียว `#2F8A3E` | — | กล่องกดเขียว |
| `silent` | **บ้านเงียบ** (ไม่ตอบเกิน 6 ชม.) | เทา `#888780` **ขอบส้ม** (ต้องเด่น ไม่ใช่จาง) | อสม. ไปเคาะ | ตัวรับ |
| `sos` | ขอความช่วยเหลือ | แดง `#D23B30` | กด "รับเรื่อง" | กล่องกดแดง |
| `auto_sos` | **กล่องขอแทน — รอ อสม. ยืนยัน** | แดง + ป้าย | อสม. ยืนยันก่อน แล้วรับเรื่อง | กล่อง (ติดเตียง น้ำขึ้น ไม่มีใครกด 2 ชม.) |
| `accepted` | ทีมรับเรื่องแล้ว | เหลือง `#E8B400` | ส่งเรือ แล้วกด "ช่วยเสร็จ" | แดชบอร์ด → ตัวรับ |
| `done` | ช่วยเสร็จ | เขียว | — | แดชบอร์ด → ตัวรับ |
| `safe` | ปลอดภัย (บ้านแจ้ง) | เขียว | — | กล่องกดเขียวค้าง |
| `offline` | ขาดการติดต่อ | เทาเส้นประ | อสม. ไปดู | ตัวรับ (เงียบเกินกำหนด และไม่มีคำขอเปิด) |

**ป้ายซ้อน (แสดงพร้อมสถานะหลัก ไม่ใช่สถานะใหม่):**

| ฟิลด์ | ป้าย | หมายเหตุ |
|---|---|---|
| `low_batt: true` | ไอคอนถ่าน "ถ่านอ่อน" | ไม่เปลี่ยนสีหลัก |
| `offline: true` (แต่ state ไม่ใช่ `offline`) | "ขาดการติดต่อ" | เกิดได้ตอนมีคำขอเปิดอยู่ คำขอต้องอยู่ในคิวเดิม + ป้ายนี้ |
| `req.cancel_t` ไม่เป็น null | "ยกเลิกโดยบ้าน ควรโทรยืนยัน" | เฉพาะบ้านติดเตียง คำขอยังอยู่ที่เดิมในคิว |
| `req.kind="auto_sos"` และ `confirmed=false` | "ขอแทน รอยืนยัน" | ปุ่มรับเรื่องจะถูกตัวรับปฏิเสธ (`need_confirm`) จนกว่าจะยืนยัน |
| `accepted` แต่ `req.delivered=false` เกิน 5 นาที | "ไฟที่บ้านยังไม่เปลี่ยน — กล่องยังไม่ได้รับ" | ตัวรับส่งซ้ำเองอยู่ |
| `probe_wet: true` | "น้ำถึงสายวัด" | **ใช่/ไม่ใช่เท่านั้น ไม่ใช่ความลึก** ห้ามแสดงเป็นตัวเลข |
| `bed: true` | "ติดเตียง" | ลำดับความเร่งสูงขึ้น |
| `last_seen: null` | "ยังไม่เคยได้ยินกล่องนี้" | |
| `try > 1` | "ส่งถึงในครั้งที่ n" | บอกว่าสัญญาณบ้านนี้ไม่ดี (แสดงเงียบ ๆ) |

**ข้อบังคับเรื่องสี (จาก design-direction):**
- ส้มกับเหลืองต้องต่างกันทั้ง **รูปร่าง/ไอคอน/คำกำกับ** ไม่ใช่แค่สี (คนตาบอดสี, จอโปรเจกเตอร์)
- เขียวมี 3 ความหมาย (`heard` `done` `safe`) แยกด้วยคำกำกับ
- สีสถานะใช้กับสถานะเท่านั้น ห้ามใช้ตกแต่งหรือเป็นสีปุ่มทั่วไป (ปุ่มหลักใช้หมึกดำ `#1F1F1D` ตัวขาว)
- `state` ที่ไม่รู้จักหรือช่องหาย → "ไม่ทราบ" สีเทา ห้ามหน้าเว็บพัง ตัวเลขที่หายแสดง "—"

## 4. ลำดับเหตุการณ์ (user flow) ที่ต้องออกแบบ

### 4.1 ส่งคำเตือน
```
ผู้ส่งเลือก "เมื่อไหร่" (วันนี้ / คืนนี้ / พรุ่งนี้) + ระดับน้ำ (ซม. ไม่บังคับ)
→ กด "ส่งคำเตือน" → ส่ง {"cmd":"warn","rid":n,"when":"tonight","lvl_cm":80}
→ รอ res ok + snap ใหม่ (warn.wid เพิ่ม, warn.active=true)
→ บ้านทยอยเปลี่ยน idle → warn → heard ภายในไม่กี่นาที
→ ตัวรับส่งซ้ำเอง (3 ครั้งห่าง 30 วิ แล้วทุก 15 นาที) จนกด "หยุดส่งซ้ำ" ({"cmd":"warn_stop","wid":7})
```
- ข้อความเตือนเป็น **ตัวเลือกตายตัว 3 แบบ** (กล่องพูดเสียงที่อัดไว้ ไม่มีข้อความอิสระ) ช่องระดับน้ำ **แสดงบนเว็บเท่านั้น** กล่องไม่ได้พูดตัวเลข
- จอที่ควรมี: ความคืบหน้า "ตอบแล้ว X / ทั้งหมด Y" · "ยังเงียบ Z (ติดเตียง W)" · "ขาดการติดต่อ K" · ส่งไปแล้วกี่รอบ (`warn.tx`) · เวลาเริ่ม

### 4.2 บ้านเงียบ / ขาดการติดต่อ → รายการ "บ้านที่ต้องไปดู"
- รวม `silent` + `offline` (และป้าย `offline:true`) ขึ้นบนสุด **ติดเตียงก่อน**
- `silent` = ได้คำเตือนแล้วเกิน 6 ชม. ไม่มีใครกด · `offline` = ไม่ได้ยินกล่องเกิน 13 ชม. (ช่วงมีคำเตือนค้าง: เกิน 3 ชม.) — ค่าออกแบบ
- `got_warn` บอกว่ากล่องรายงานแล้วว่าได้รับคำเตือนปัจจุบันหรือยัง (แยก "ได้แต่ไม่ตอบ" กับ "ไม่แน่ใจว่าได้")
- ไม่มีปุ่มสั่งกล่องในกรณีนี้ การกระทำคือส่งคนไปดู (ออกแบบให้เห็นตำแหน่ง/ชื่อบ้าน/ติดเตียงชัด)

### 4.3 คำขอความช่วยเหลือ (SOS)
```
บ้านกดแดงค้าง 2 วิ → state=sos, req เปิด (req.no, t_open)
→ ทีมกด "รับเรื่อง" → {"cmd":"accept","rid":n,"id":1001} → state=accepted, กล่องเป็นเหลือง + พูด
→ (req.delivered=true เมื่อกล่องตอบรับแล้ว)
→ ทีมช่วยเสร็จ กด "ช่วยเสร็จ" → {"cmd":"done","rid":n,"id":1001} → state=done, ปิดคำขอ
```

### 4.4 ขอแทนอัตโนมัติ (บ้านติดเตียง)
```
น้ำถึงสายวัด (probe_wet=true, t_wet) + ไม่มีใครกดปุ่ม 2 ชม. → กล่องส่งเอง → state=auto_sos, confirmed=false
→ อสม. ไปดู/โทร แล้วกด "ยืนยัน" ({"cmd":"confirm","id":...}) → confirmed=true
→ ทีมกด "รับเรื่อง" → accepted → done
```
- ระหว่างนับ 2 ชม. แสดงนับถอยหลังได้จาก `t_wet` (ช่วยทีมเตรียมตัว) — ข้อเสนอ ไม่บังคับ
- ถ้าคนในบ้านกดแดงเองระหว่างนั้น คำขอเปลี่ยนเป็น `kind="sos"`

### 4.5 บ้านกดเขียวค้าง (ปลอดภัย / ยกเลิก)
- **บ้านทั่วไป:** คำขอถูกปิดทันที → `state=safe` ("ปลอดภัย (บ้านแจ้ง)")
- **บ้านติดเตียง:** คำขอ **ไม่ปิด** → ขึ้นป้าย "ยกเลิกโดยบ้าน ควรโทรยืนยัน" (`req.cancel_t`) คำขออยู่ที่เดิมในคิว มี 2 ปุ่มข้างกัน:
  - "โทรแล้ว ปลอดภัย" → `{"cmd":"cancel_ok","id":...}` → `safe` (ไม่ส่งอะไรถึงกล่อง กล่องเขียวอยู่แล้ว)
  - "รับเรื่อง" (ทีมยังจะไป) → `accepted`

### 4.6 ลำดับคิวคำขอ (ค่าออกแบบ)
1. `auto_sos` (กล่องขอแทน)
2. `sos` ของบ้านติดเตียง
3. `sos` อื่น ๆ เรียงตามเวลาที่เปิด (`t_open` เก่าก่อน)
4. `accepted` (รับแล้ว รอช่วยเสร็จ)

## 5. ข้อมูลที่หน้าจอได้รับ (สรุปจาก data-contract ข้อ 5.2)

ตัวรับส่ง JSON บรรทัดละก้อน 3 ชนิด: `snap` (ภาพรวมทั้งหมด), `hb` (ทุก 2 วิ บอกว่ายังต่ออยู่), `res` (ผลของคำสั่ง)

**`snap` ระดับบน:**

| ช่อง | ใช้ทำอะไรบนจอ |
|---|---|
| `rev` | ตัวนับการเปลี่ยนแปลง ใช้เช็กว่าข้อมูลบนจอเป็นชุดล่าสุด |
| `now` | เวลาตัวรับ (วินาที) ใช้แปลงเวลา |
| `gw.name` / `gw.sim` / `gw.link` / `gw.air_pct` | ชื่อตัวรับ · `sim=true` → ป้าย "จำลอง" · ช่องทาง · % เวลาออกอากาศ (แสดงเล็ก ๆ ในหน้าสถานะระบบ) |
| `cfg.*` | ค่าออกแบบที่ใช้อยู่ (6 ชม., 2 ชม., 13 ชม. …) ใช้เขียนคำอธิบายบนจอให้ถูก ต้องมีป้าย "ค่าออกแบบ จะปรับหลังทดสอบ" |
| `warn` | คำเตือนปัจจุบัน: `wid`, `when`, `lvl_cm`, `t`, `tx` (ส่งไปกี่รอบ), `active` · null = ไม่มี |
| `houses[]` | ทุกบ้าน (ตารางข้างล่าง) |
| `events[]` | 50 เหตุการณ์ล่าสุด `{t, id, ev}` ใช้ทำแถบ "เกิดอะไรขึ้นบ้าง" |

**แต่ละบ้าน `houses[i]`:**

| ช่อง | ความหมาย | แสดงแบบไหน (ข้อเสนอ) |
|---|---|---|
| `id` | รหัสบ้าน 1–65534 | ตัวเลข monospace |
| `name` | ชื่อบ้าน เช่น "บ้าน 12" | ชื่อหลักของการ์ด |
| `x`, `y` | ตำแหน่งบนแผนที่ชุมชน (เมตร) | หมุดบนแผนที่ที่วาดเอง (ไม่มีแผนที่ออนไลน์) |
| `bed` | บ้านติดเตียง | ป้าย/ไอคอน "ติดเตียง" |
| `state`, `t_state` | สถานะ + เวลาที่เข้าสถานะนี้ | สี + คำ + "ตั้งแต่ hh:mm (x นาทีที่แล้ว)" |
| `got_warn` | ได้คำเตือนปัจจุบันแล้ว | ใช้ในหน้าความคืบหน้าคำเตือน |
| `last_seen` | ได้ยินกล่องล่าสุด | "ได้ยินล่าสุด hh:mm" / "ยังไม่เคยได้ยิน" |
| `offline` | ขาดการติดต่อ | ป้ายซ้อน |
| `rssi`, `snr` | ความแรงสัญญาณ | **แสดงเฉย ๆ** ในรายละเอียด ไม่ใช้ตัดสินอะไร |
| `batt_v`, `low_batt` | แรงดันถ่าน / ถ่านอ่อน | ตัวเลข V ในรายละเอียด + ป้าย |
| `probe_wet`, `t_wet` | น้ำถึงสายวัด / เวลาที่น้ำขึ้น | ใช่/ไม่ใช่ ห้ามแสดงความลึก |
| `try` | ข้อความล่าสุดถึงในครั้งที่เท่าไร | เล็ก ๆ |
| `req` | คำขอที่เปิดอยู่ (มีได้ 1): `no`, `kind`, `t_open`, `confirmed`, `t_accept`, `delivered`, `cancel_t`, `dup` | การ์ดคิวคำขอ · `dup` = กดซ้ำกี่ครั้ง (บอกความกังวลของบ้าน) |

**ชนิด `events[].ev`:** `warn_sent` `heard` `silent` `sos` `auto_sos` `confirm` `accept` `delivered` `done` `safe` `cancel` `cancel_ok` `low_batt` `probe_wet` `probe_dry` `offline` `online` `retry_rx` — ต้องมีคำไทยของทุกตัว

ตัวอย่างข้อมูลเต็ม 3 สถานการณ์: `docs/data-contract.md` ข้อ 5.5 · ข้อความจากบอร์ดตัวรับจริง (บ้าน 1 หลัง): `docs/test-logs/b3-receiver-raw.log` · จากตัวรับจำลองบนคอม (โค้ดเดียวกับบอร์ด): `docs/test-logs/a3-dashboard-serial.log`

## 6. ปุ่ม คำสั่ง และการตอบกลับ

### 6.1 คำสั่งทั้งหมด

| ปุ่มบนจอ (ข้อเสนอ) | คำสั่ง | ใช้ได้เมื่อ | ตัวรับอาจปฏิเสธด้วย |
|---|---|---|---|
| (อัตโนมัติตอนต่อ) | `hello` | เปิดพอร์ตแล้ว | — |
| ส่งคำเตือน | `warn` + `when`, `lvl_cm` | ทุกเมื่อ | `bad_when` |
| หยุดส่งซ้ำ | `warn_stop` + `wid` | มีคำเตือน active | `no_warn` |
| ยืนยันคำขอแทน | `confirm` + `id` | `auto_sos` ที่ `confirmed=false` | `no_open_request` `not_auto` |
| รับเรื่อง | `accept` + `id` | มีคำขอเปิด (auto ต้องยืนยันก่อน) | `no_open_request` `need_confirm` |
| ช่วยเสร็จ | `done` + `id` | มีคำขอเปิด | `no_open_request` |
| โทรแล้ว ปลอดภัย | `cancel_ok` + `id` | `req.cancel_t` ไม่เป็น null | `no_open_request` `not_cancelled` |

### 6.2 กติกาของปุ่ม (สำคัญต่อ UX)
- **ห้ามเปลี่ยนสถานะบนจอทันทีที่กด** ให้ปุ่มเข้าสถานะ "กำลังส่ง…" แล้วรอ `res` + `snap` ใหม่ยืนยัน
- ไม่ได้ `res` ใน 5 วิ หรือ `ok:false` → ข้อความข้างปุ่ม "ส่งคำสั่งไม่สำเร็จ ลองใหม่" (+ แปล `err` เป็นภาษาคน เช่น `need_confirm` = "ต้องให้ อสม. ยืนยันก่อน")
- คำสั่งซ้ำไม่อันตราย กดซ้ำได้
- ปุ่มที่มีผลกับบ้านจริง (รับเรื่อง, ช่วยเสร็จ, ปลอดภัย) ควรกันกดพลาด แต่ห้ามช้าเกินไป (เช่น กดค้าง หรือ ยืนยันในที่เดียว ไม่ใช่กล่องถามซ้อน 2 ชั้น) — ข้อเสนอ ให้ผู้ออกแบบเลือก
- ปุ่มคำสั่งทั้งหมด **กดไม่ได้** ตอนขาดการเชื่อมต่อกับตัวรับ หรืออยู่โหมดจำลอง (โหมดจำลองให้กดแล้วจำลองผลได้ แต่ต้องรู้ชัดว่าไม่ใช่ของจริง)

### 6.3 ลำดับตอนเชื่อมต่อ
1. ผู้ใช้กด "เชื่อมต่อตัวรับ (สาย USB)" (Web Serial บังคับต้องมีการกดครั้งแรก)
2. เบราว์เซอร์ถามให้เลือกพอร์ต → เลือกตัวรับ (บนเครื่องที่ทดสอบ Windows แสดงบอร์ดเป็น "USB Serial Device (COMx)" ทั้งสองบอร์ด ต่างกันแค่เลข COM ระวังสับสนถ้าเสียบสองบอร์ด)
3. เว็บส่ง `hello` → ได้ `snap` → แสดงผล
4. ครั้งต่อไปเบราว์เซอร์จำพอร์ตได้ → ต่อเองได้โดยไม่ต้องกด

### 6.4 เวลา
- ตัวรับไม่มีนาฬิกาจริง ทุกช่อง `t*`, `now`, `last_seen` = วินาทีนับจากตัวรับเปิดเครื่อง
- แปลง: `เวลาจริง = Date.now()/1000 − (now − t)` แล้วแสดงเป็น "hh:mm" + "x นาทีที่แล้ว"
- ถ้า `now` ถอยหลัง = ตัวรับรีสตาร์ต → ขอ `snap` ใหม่ทั้งหมด (ข้อมูลเดิมในตัวรับหายได้ ควรมีข้อความบอก)

## 8. ข้อจำกัดที่ต้องเคารพ

- **ไม่มีอินเทอร์เน็ต:** ไม่มี CDN, ไม่มี web font ภายนอก, ไม่มี tile แผนที่ออนไลน์ · แผนที่ชุมชนวาดเองจาก `x`,`y` · ฟอนต์ใช้ของเครื่อง: ไทย `"Leelawadee UI", "Noto Sans Thai", Tahoma, sans-serif` · ตัวเลข `Consolas, "Cascadia Mono", monospace`
- **เว็บ static:** ไม่มี backend, ไม่มี build step (ขึ้น GitHub Pages ได้ และเปิดจาก `http://127.0.0.1` ได้)
- **จอ:** โน้ตบุ๊กเป็นหลัก แต่ควรใช้บนโปรเจกเตอร์ตอนพรีเซนต์ได้ (ตัวใหญ่ คอนทราสต์สูง)
- **ห้ามแต่งตัวเลข:** ช่องผลทดสอบที่ยังไม่มีให้ใช้กรอบเส้นประ "รอผลทดสอบ" · ค่าที่ออกแบบเองใส่ป้ายเล็ก "ค่าออกแบบ จะปรับหลังทดสอบ"
- **ห้าม:** โลโก้หน่วยงานรัฐจริง · ข้อมูลบุคคลจริง (ชื่อบ้านในเดโมเป็นข้อมูลสมมติ) · อีโมจิเป็นไอคอน · สีสถานะไปตกแต่ง
- **ทิศทางหน้าตาเดิม** ("แบบแปลนวิศวกร" ขาว-เทา เส้นบาง สีสดเฉพาะสถานะ) อยู่ที่ `docs/design-direction.md` ถ้าจะเปลี่ยนทิศทาง ให้คุยกับเจ้าของโปรเจกต์ก่อน

## 9. หน้าจอที่น่าจะต้องมี (ข้อเสนอ ปรับได้)

1. **หน้าหลัก (ภาพรวม):** แถบเชื่อมต่อ · ตัวเลขใหญ่ (คำขอรอรับ / ยังเงียบ / ขาดการติดต่อ) · แผนที่ชุมชน + หมุด · คิวคำขอ · รายการบ้านที่ต้องไปดู
2. **การ์ด/แผงรายละเอียดบ้าน:** ทุกช่องในหัวข้อ 5 + ปุ่มที่ใช้ได้ตามสถานะ + ประวัติเหตุการณ์ของบ้านนี้
3. **ส่งคำเตือน:** ตัวเลือก 3 แบบ + ระดับน้ำ + ความคืบหน้า + หยุดส่งซ้ำ
4. **บันทึกเหตุการณ์:** จาก `events[]` (ล่าสุด 50 รายการ)
5. **สถานะระบบ:** ตัวรับ, เวลาออกอากาศ, ค่าออกแบบ (`cfg`) พร้อมป้าย
6. **โหมดจำลอง/พรีเซนต์:** แดชบอร์ดเดิมมี `?demo=auto` (เดโม 60 วิ) และปุ่มทดลองกับบ้านที่เลือก (กดเขียว, กดแดงค้าง, น้ำถึงสายวัด, ถ่านอ่อน, ปลอดภัย, ขาดการติดต่อ) ควรเก็บความสามารถนี้ไว้ พร้อมป้าย "จำลอง" + "เดโมเร่งเวลา"

ทุกส่วนต้องออกแบบสถานะ: ว่าง (ยังไม่มีบ้าน/ยังไม่ต่อ) · ปกติ · มีเหตุเยอะ (เช่น 50+ บ้าน) · ข้อมูลจาง (ขาดการเชื่อมต่อ) · ผิดพลาด

## 10. คำถามที่ยังเปิดอยู่ (เกี่ยวกับหน้าจอ)
1. บ้านติดเตียงกดปลอดภัย กล่องพูด "ยกเลิกคำขอแล้ว…" ทั้งที่คำขอยังค้างบนแดชบอร์ดรอโทร — หน้าจอควรอธิบายให้ทีมเข้าใจยังไง
2. ระดับน้ำในคำเตือน แสดงบนเว็บเท่านั้น กล่องไม่พูดตัวเลข — ควรมีช่องนี้ไหม
3. ระหว่างนับ 2 ชม. ก่อนขอแทน ควรแสดงนับถอยหลังบนจอไหม
4. ถ้าวันหน้าตัวรับปล่อย Wi-Fi ให้มือถือเปิดได้ (data-contract ข้อ 9) ข้อมูลเป็นรูปเดียวกัน — ออกแบบให้ใช้บนมือถือได้ด้วยตั้งแต่ตอนนี้ไหม

## 12. ส่งอะไรกลับมา (ข้อเสนอ)
- โครงหน้าจอ (wireframe) ของหัวข้อ 9 ทุกหน้า + สถานะว่าง/ปกติ/เหตุเยอะ/ขาดการเชื่อมต่อ/ผิดพลาด
- ชุดสี/ไอคอนของ 10 สถานะ + ป้ายซ้อน (ผ่านเกณฑ์ตาบอดสี ส้ม ≠ เหลือง)
- คำบนจอภาษาไทยทุกคำ (สถานะ, events, ข้อความผิดพลาด, ปุ่ม)
- ถ้าทำเป็นโค้ด: เว็บ static ไฟล์ HTML/CSS/JS ไม่มี build ไม่โหลดอะไรจากเน็ต อ่าน `snap`/`hb`/`res` และส่ง `cmd` ตามหัวข้อ 5–6
